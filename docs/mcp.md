# Управление идеями через агента

[Русский](mcp.md) · [English](en/mcp.md)

MCP позволяет агенту искать, читать, создавать и редактировать идеи, работать с блоками и прикреплять оригиналы медиафайлов. Например:

> Создайте в разделе Gamedev идею «Лесная станция». Добавьте блок о восстановлении заброшенной станции и приложите это изображение.

> Найдите идею про станцию в лесу и расскажите, что в ней уже записано.

Агент выбирает подходящую идею по названию и описанию, затем читает её содержимое. Если подходят несколько записей, он должен уточнить выбор. Поиск учитывает простые опечатки; отдельный сервис векторного поиска не используется.

Выберите подключение к нужной библиотеке. Локальный STDIO работает с файлами на компьютере, облачный Streamable HTTP обращается к сайту. Подключать оба варианта не требуется; данные между ними автоматически не переносятся.

## Подключение локальной библиотеки

После `npm ci` добавьте сервер в настройках MCP клиента Codex. Тип подключения: **STDIO**.

| Поле | Значение |
| --- | --- |
| Имя | `idea-bank-local` |
| Команда | Полный путь к `node.exe` или `node` из PATH |
| Аргументы | `--import`, файловый URL загрузчика `node_modules/tsx/dist/loader.mjs`, полный путь к `scripts/mcp-local.mts` |

Путь к Node.js в PowerShell можно получить командой `(Get-Command node).Source`. Для загрузчика используйте файловый URL: `file:///C:/path/to/idea-bank/node_modules/tsx/dist/loader.mjs`. Он позволяет запускать MCP из другой рабочей папки. Обычный абсолютный Windows-путь в `--import` не подходит. Пробелы в URL заменяются на `%20`; путь к самому скрипту остаётся обычным файловым путём.

Пример настройки в `config.toml` Codex, с путями, заменёнными на ваши:

```toml
[mcp_servers.idea-bank-local]
command = "C:/Program Files/nodejs/node.exe"
args = ["--import", "file:///C:/Apps/idea-bank/node_modules/tsx/dist/loader.mjs", "C:/Apps/idea-bank/scripts/mcp-local.mts", "--allow-files", "C:/Users/owner/Pictures/IdeaBank"]
startup_timeout_sec = 30
tool_timeout_sec = 120
```

Сервер использует ту же папку `data`, что и приложение, либо значение `IDEA_BANK_DATA_DIR`. Параметр `--data-dir C:/path/to/library` выбирает другую библиотеку для этого подключения. Для доступа только на чтение добавьте `--read-only`.

Ссылки на идеи по умолчанию ведут на `http://127.0.0.1:3000`. Если приложение запущено на другом порту, задайте, например, `--app-url http://127.0.0.1:3001`. Этот параметр задаёт только ссылки для открытия в браузере; MCP продолжает читать выбранную дисковую библиотеку напрямую.

`--allow-files` разрешает прикреплять файлы из указанной папки; его можно повторить для нескольких папок. Выбирайте папки с материалами для идей. По умолчанию разрешена только `public/examples` приложения. Переданный агенту путь за пределами разрешённых папок будет отклонён.

Codex запускает отдельный MCP-процесс для соединения и использует его для нескольких вызовов инструментов. Веб-приложение запускать не требуется. Если оно открыто, сохранённые изменения приходят в интерфейс через локальные события файловой системы. Периодического опроса библиотеки нет.

Перед копированием или переносом `data` остановите веб-сервер и отключите локальное MCP-подключение, чтобы завершить его процесс. После переноса приложения обновите путь к загрузчику и скрипту в настройках клиента, затем включите подключение. Путь `--allow-files` и абсолютный `--data-dir` также обновляются при переносе соответствующих папок.

Подключение находится в **Settings → MCP servers**; в CLI список показывает `codex mcp list`. Настройки хранятся в `~/.codex/config.toml` или в `.codex/config.toml` доверенного проекта. Подключение инструментов не переносится автоматически вместе с папкой приложения.

Встроенная команда `npm run mcp:local` предназначена для запуска MCP-клиентом. При ручном запуске она ожидает сообщения протокола, а не открывает сайт.

## Подключение облачной библиотеки

Требуется настроенный [облачный экземпляр](deployment.md) с GitHub-входом и B2. По умолчанию облачный MCP выключен. Этот раздел нужен только для управления облачной библиотекой через агента; обычная работа на сайте и локальный STDIO его настройки не требуют.

1. В существующей GitHub App добавьте ещё один **Callback URL**: `https://your-site.vercel.app/api/mcp/oauth/callback`. Сохраните прежний callback `/api/auth/callback/github` для входа на сайт. Homepage URL менять не требуется.
2. В Production-переменные Vercel добавьте `IDEA_BANK_MCP_ENABLED=true` и выполните Redeploy. Дополнительные ключи или сервисы авторизации не нужны.
3. В Codex добавьте MCP-сервер типа **Streamable HTTP** с адресом `https://your-site.vercel.app/api/mcp` и именем `idea-bank-cloud`.
4. Нажмите **Authenticate**, войдите как владелец Idea Bank и подтвердите доступ агента. В CLI те же действия начинаются командами:

```sh
codex mcp add idea-bank-cloud --url https://your-site.vercel.app/api/mcp
codex mcp login idea-bank-cloud
```

Для локальной проверки облачного режима callback имеет вид `http://127.0.0.1:3000/api/mcp/oauth/callback`, а приложение запускается через `npm run dev` с `IDEA_BANK_AUTH_MODE=github`. `mcp:local` всегда обращается к дисковой библиотеке и для такой проверки не подходит.

Подключение использует OAuth с PKCE и существующую GitHub App. Разрешения: `ideas:read` и `ideas:write`; при запросе только `ideas:read` инструменты записи недоступны. Регистрация клиента и проверка токена не обращаются к B2. Одноразовые коды и обновление GitHub-токенов проверяются GitHub. Параметр `offline_access` запрашивает обновляемый вход.

Токен доступа MCP действует до пяти минут. При выданном refresh token клиент может обновить его; без refresh token после истечения срока потребуется новый вход. Отключение сервера в Codex прекращает использование подключения. Для отзыва авторизации откройте GitHub → Settings → Applications → Authorized GitHub Apps и отзовите доступ собственной GitHub App. Уже выданный MCP-токен может действовать ещё до пяти минут; отзыв приложения также затрагивает его другие подключения. Для немедленного выключения всего облачного MCP удалите `IDEA_BANK_MCP_ENABLED=true` и повторно разверните сайт.

Изменения агента сохраняются через обычный механизм версий и уведомлений Ably. На телефоне достаточно открыть сайт; агент на телефоне не требуется. Дисковая библиотека и облачный экземпляр остаются независимыми, перенос между ними выполняется через ZIP.

## Передача медиа

В локальном подключении агент передаёт абсолютный путь к оригиналу из разрешённой папки; скачиваемый HTTPS-адрес также допустим. В облачном подключении клиент должен предоставить скачиваемый HTTPS-адрес файла. Поддержка передачи приложенного к чату оригинала зависит от клиента; само наличие картинки в сообщении не гарантирует, что клиент отдаст её файл инструменту. Для клиентов с передачей файлов объявлен [формат FileRef](https://developers.openai.com/plugins/reference#define-file-inputs): `download_url`, `file_id` и необязательные `file_name`, `mime_type`. Если тип не передан, используется Content-Type ответа при скачивании.

Если облачный клиент не передаёт оригинал, агент вызывает `prepare_attachment` и выдаёт ссылку на страницу загрузки. Владелец открывает её, выбирает оригинал и сообщает агенту о завершении. Файл отправляется напрямую в закрытый B2, затем прикрепляется к выбранной идее. Агент повторно читает идею после подтверждения, без опроса статуса загрузки. Ссылка действует один час и требует входа владельца. При конфликте агент получает актуальную версию и согласует повторное прикрепление.

В локальном STDIO страницы загрузки нет. Если клиент не передаёт оригинал, сохраните файл в папке, разрешённой через `--allow-files`, и укажите агенту его абсолютный путь.

Ограничения:

- Прямая передача через MCP: до 64 МиБ на файл. Через страницу загрузки: до 1 ГиБ.
- Предпросмотр изображения инструментом `get_media`: до 8 МиБ. Остальные файлы возвращаются как метаданные и ссылка на оригинал.
- Составной glTF нужно заранее объединить в GLB или самодостаточный glTF. SVG не принимается.
- Скачивание с локальных и служебных сетевых адресов блокируется. Облачный сервер не читает пути файлов на вашем компьютере.
- Подписанные ссылки, ссылки загрузки и токены не следует публиковать.
- Для идеи с большим количеством блоков ссылка загрузки может не поместиться в допустимый размер. В этом случае используется прямая передача через `attach_media`.

## Инструменты и правила записи

| Инструмент | Назначение |
| --- | --- |
| `list_sections` | Названия и идентификаторы разделов |
| `search_ideas` | Поиск карточек по названию и описанию; `content=true` включает ограниченный поиск по содержимому |
| `get_idea` | Содержимое одной идеи и версия для редактирования |
| `get_media` | Метаданные, ссылка и необязательный предпросмотр одного вложения |
| `create_section` | Создание раздела по поручению пользователя |
| `create_idea` | Создание идеи в существующем разделе |
| `update_idea` | Изменение свойств идеи, добавление, изменение, перемещение и удаление её блоков |
| `attach_media` | Прикрепление оригинала в блок или в качестве обложки |
| `prepare_attachment` | Ссылка на загрузку, когда клиент не может передать оригинал |

Удаления всей библиотеки, разделов и идей через MCP нет. Замена текста блока передаёт обычный текст и сбрасывает форматирование именно этого текста; остальные поля и медиа сохраняются.

Каждая запись требует UUID v4 в `operation_id`. При потере ответа повторяются тот же идентификатор, версия и аргументы. Для нового изменения нужен новый идентификатор. `update_idea` и `attach_media` требуют `version` из последнего чтения или успешной записи. При конфликте инструмент возвращает ошибку, не перезаписывая чужие правки. Агент должен перечитать идею и проверить своё изменение.

Содержимое идей рассматривается как данные. Инструкции внутри заметок не разрешают агенту выполнять команды или обращаться к другим ресурсам. Разрешения самого Codex продолжают действовать: если клиент запросил подтверждение правки, её нельзя считать выполненной до успешного ответа инструмента.

Облачный агент видит сохранённые в B2 записи. Несохранённые черновики и очередь браузера ему недоступны. При активном редактировании входящие изменения не должны заменять введённый текст; обычная проверка версий остаётся обязательной.

## Для разработчика и проверок

Транспорт HTTP находится в `lib/mcp-http.ts`, инструменты и схемы в `lib/mcp-server.ts`. `LocalAgentBackend` использует транзакции `DiskLibraryStore`, `CloudAgentBackend` использует `EntityStorage`, `CatalogStorage` и обычные события синхронизации. Авторизация вынесена в `lib/mcp-auth.ts` и `lib/mcp-consent.ts`.

Инициализация и получение списка инструментов не читают библиотеку. Обычный поиск просматривает до 100 карточек за страницу; явный поиск по содержимому читает до 10 идей за страницу. Следующая страница запрашивается только при необходимости. Оригиналы медиа не включаются в ответы чтения идеи.

```sh
npm run test:mcp
npm run test:mcp-auth
npm run build
npm run test:mcp-http
npm run test:requests
```

Проверки используют временные библиотеки и синтетические настройки. Дополнительно `npm run test:mcp-codex` запускает настоящий установленный Codex CLI с существующим входом и расходует его обычный лимит. Он создаёт тестовую библиотеку в `.cache`, проверяет команды, оригинал PNG, предпросмотр, поиск и сохранённую правку, затем удаляет библиотеку. Настройки основного клиента не меняются. Реальный облачный вход и доступ к B2 проверяются отдельно после настройки своего экземпляра; синтетический тест их не заменяет.

Локальный STDIO проверен настоящим Codex CLI на изолированной библиотеке. Облачный HTTP и авторизация покрыты синтетическими тестами; полный сценарий с реальными GitHub OAuth и B2 требует отдельной проверки владельцем. Совместимость с другими MCP-клиентами не подтверждена. Настройки клиента приведены по [официальной документации Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
