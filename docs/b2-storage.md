# Хранение и синхронизация

Тексты и медиа хранятся вместе в закрытом Backblaze B2. Настройка хранилища и CORS приведена в [руководстве по развёртыванию](deployment.md).

## Автоматическая синхронизация

Сохранение записывает изменения в IndexedDB вместе с очередью отправки. Через 1,2 секунды приложение начинает синхронизацию. При настроенном Ably сервер отправляет уведомление после сохранения облачной версии; остальные устройства проверяют индекс и получают изменения из B2. Уведомление содержит только идентификатор версии и номер протокола, без содержимого идей и файлов.

При рабочей подписке страховочная проверка выполняется раз в 10 минут. Без Ably или при недоступности подписки облако проверяется раз в минуту. Проверка также запускается при открытии, возврате в приложение и восстановлении соединения. После временной ошибки хранения повторные попытки выполняются с увеличением интервала до 5 минут.

Во время редактирования, импорта и экспорта новые проверки и применение входящих изменений откладываются. После завершения операции синхронизация продолжается. Вкладки одного браузера используют общую блокировку, чтобы не отправлять изменения одновременно. В скрытой вкладке подписка закрывается, периодические проверки приостанавливаются. В закрытой вкладке синхронизация не выполняется.

[Подключение Ably](deployment.md#уведомления-об-изменениях-необязательно) не меняет хранение данных и правила разрешения конфликтов. Браузер получает токен на 15 минут с правом подписки на один канал. Ключ Ably остаётся на сервере. Ошибка уведомления не отменяет сохранение в B2: пропущенное изменение обнаружится при следующей проверке.

Новое устройство автоматически получает разделы и первую страницу карточек. После очистки данных сайта они загружаются тем же способом; очистка кеша не отправляет удаление в облако. Если облачная библиотека ещё не создана, стартовый Example сохраняется в B2. Намеренно пустая облачная библиотека остаётся пустой.

При наличии собственных локальных идей источник выбирает владелец. Любое сохранение или импорт снимает признак нетронутого стартового примера. После подключения направление определяется версиями записей и состоянием предыдущей синхронизации. Часы устройства не определяют победившую версию.

| Изменения | Действие |
| --- | --- |
| Только локальные | Отправка изменённых записей |
| Только облачные | Обновление карточек и открытой идеи; остальные идеи проверяются при открытии |
| Независимые правки идей, блоков или полей | Объединение |
| Несовместимые правки одной записи, удаление против изменения | Выбор владельцем |
| Данные совпадают | Проверка версий без передачи содержимого записей |

Состояние отображается в верхней панели. При конфликте откройте меню синхронизации, сравните версии и примените выбранные варианты. При истечении сессии войдите снова. Кнопка **Синхронизировать** позволяет запустить проверку вручную.

## Загрузка идей и локальный кеш

Каталог передаётся порциями по 24 карточки, без текстов блоков. Поиск выполняется по названиям и описаниям. При открытии идеи сервер сверяет её версию с сохранённой на устройстве: неизменившаяся версия возвращает `304`, изменившаяся передаётся с содержимым блоков. Версия учитывает ревизии идеи, её блоков и родительского раздела.

Сохранение отправляет изменения выбранной идеи или раздела. При удалении раздела учитываются все входящие в него идеи. Уведомления Ably обновляют каталог и открытую идею, не скачивая содержимое закрытых идей.

Поиск и прокрутка не перезагружают неизменившуюся боковую панель. Локальные изменения очереди отображаются из сохранённых данных; после отправки пачки выполняется одна облачная проверка.

Вместе с открываемой идеей передаются номера базовых версий её записей. Редактор блоков использует соответствующую локальную копию без дополнительного запроса перед началом работы. Перед отправкой правок облачная версия проверяется повторно, с прежними правилами объединения и разрешения конфликтов.

Повторные сигналы обновления объединяются. При отказе B2 из-за доступа или лимитов автоматические обращения приостанавливаются на пять минут; ручная синхронизация позволяет повторить проверку раньше. Сохранённые данные остаются видимыми с отметкой недоступности облака, очередь изменений сохраняется.

Сервер повторно использует неизменяемые объекты каталога и версии записей: до 8 МиБ JSON и 256 объектов на экземпляр, не дольше пяти минут. Одновременные чтения одного объекта объединяются. Текущая версия библиотеки проверяется в B2 при каждом запросе, поэтому новые записи видны без ожидания истечения кеша. Ошибки и отсутствие объектов не кешируются; проверки существования перед записью остаются прямыми. Новый экземпляр Vercel начинает с пустым кешем.

Кеш карточек и текстов в IndexedDB ограничен 32 МиБ, 20 страницами каталога и 20 записями идей, включая базовые версии для редактирования. Очередь неотправленных изменений хранится отдельно и не вытесняется кешем. Эти ограничения действуют для облачного режима; в локальном режиме IndexedDB хранит исходную библиотеку.

Черновики блоков с доступными вложениями сохраняются отдельно от кеша и очереди после секундной паузы ввода. Они не отправляются в облако и не включаются в ZIP сохранённой библиотеки. Восстановление требует выбора пользователя; изменившиеся блоки сначала показываются для сравнения. Сохранение идеи или подтверждённая отмена удаляет её черновик. Очистка данных сайта удаляет и черновики.

Файлы загружаются при первом появлении превью в видимой области; одновременно скачиваются не более двух файлов в одной вкладке. Прокрутка не сбрасывает загруженное превью. После загрузки проверяются SHA-256, MD5 и размер. Запросы ссылок на медиа учитывают общую паузу после отказа B2.

Кеш подтверждённых облачных файлов ограничен 128 МиБ. При его заполнении удаляются давно не использованные копии. Файл больше этого лимита можно просмотреть без сохранения в кеше. Неотправленные оригиналы не участвуют в очистке: для них требуется отдельное свободное место.

Без сети доступны только сохранённые страницы, идеи и вложения. Интерфейс отмечает их как офлайн-копии. После вытеснения данных из кеша для повторного просмотра нужна сеть. Экспорт ZIP намеренно загружает всю библиотеку и отсутствующие оригиналы из облака; при ошибке получения файла полный архив не создаётся.

Лимиты кеша не ограничивают всю оперативную память приложения: открытая идея, показанные карточки и операции с ZIP также занимают память. Сервер сохраняет общий индекс версий; его размер и построение каталога ограничены объёмом JSON и ресурсами хостинга. Порционная загрузка не отменяет эти ограничения.

## Сохранность и обновление старой библиотеки

Медиа отправляются до публикации ссылок на них. Версии записей и индексов сохраняются отдельными неизменяемыми объектами. Повтор после потери ответа использует сохранённый идентификатор операции. Полученные записи, очередь и контрольная точка синхронизации фиксируются одной локальной транзакцией; устаревшая вкладка не может перезаписать более новые данные.

При первом запуске локальные данные прежнего формата переносятся в IndexedDB. Старые localStorage и база медиа остаются без изменений как резервная копия; их объём не входит в лимит нового кеша. Не очищайте данные сайта ради перехода.

При обновлении уже синхронизированной библиотеки каталог чтения строится автоматически, без переноса текстов всех идей на устройство. После успешного чтения каталога подтверждённая полная локальная копия и её контрольная точка освобождаются. Очередь отправки или незавершённая операция блокируют эту очистку. Исходная резервная копия старого формата не импортируется повторно. Неотправленная локальная библиотека сначала проходит существующее согласование источника и синхронизацию.

Экспорт, импорт и сброс библиотеки остаются операциями над всей библиотекой. Они временно собирают полную копию и используют совместимый протокол синхронизации; обычное чтение и редактирование этого не требуют.

Для перехода существующей облачной библиотеки:

1. Сохраните ZIP-копию и обновите приложение на всех устройствах.
2. Откройте синхронизацию и нажмите **Перейти на новую синхронизацию**.
3. Если запрошен источник библиотеки, выберите его после просмотра данных.
4. На остальных устройствах откройте обновлённое приложение и проверьте получение изменений.

Переход не удаляет прежние снимки и медиа. После него старые версии приложения больше не могут записывать библиотеку. Не выполняйте откат на старую сборку для продолжения синхронизации.

Облачные объекты расположены в:

- `idea-bank/v1/sync-v2/records/`: версии разделов, идей, блоков и описаний медиа;
- `idea-bank/v1/sync-v2/indexes/`: индексы изменений;
- `idea-bank/v1/sync-v2/catalog-v1/`: производный каталог, страницы карточек и ссылки на версии идей;
- `idea-bank/v1/media/`: оригиналы вложений;
- `idea-bank/v1/revisions/`: снимки прежнего формата.

История и облачные вложения автоматически не очищаются. Не включайте правила их удаления. История не заменяет отдельную [ZIP-копию](../README.md#резервные-копии).

Подписанные ссылки действуют 5 минут и до истечения срока дают доступ к файлу без входа. Не публикуйте их. Ключи B2 остаются на сервере.

## Технические ограничения

| Данные | Лимит |
| --- | --- |
| JSON-объект в B2 или JSON-запрос | 3 МиБ, без медиа |
| Изменения в одной отправке | 10 000 записей |
| История нового формата | 100 000 индексов |
| Родители объединённой версии | 16 |
| Один медиафайл | 1 ГиБ |
| Кеш облачных файлов | 128 МиБ |
| Кеш карточек и текстов | 32 МиБ, до 20 страниц и 20 записей идей |

Передача больших файлов не возобновляется с места обрыва. Ограничения сервисов и свободное место браузера также влияют на доступный объём.

## API

Запросы требуют сессии владельца. Для POST и PUT нужен `Origin`, совпадающий с `AUTH_URL`; HTTP-ответы отправляются с `private, no-store`.

| Запрос | Назначение |
| --- | --- |
| `GET /api/sync` | Состояние формата, без его изменения |
| `GET /api/catalog?limit=24&cursor=...&sectionId=...&q=...` | Разделы, счётчики, страница карточек и курсор продолжения |
| `GET /api/ideas/<id>` | Одна идея; `If-None-Match` позволяет получить `304` без тела |
| `GET /api/catalog/media?id=<id>` | Подписанная ссылка на вложение без полной локальной контрольной точки |
| `POST /api/sync/scoped` | `{target, includeIdeas?, includeMedia?}`: версии выбранной идеи или раздела |
| `PUT /api/sync/scoped` | `{operationId, heads, changes}`: отправка выбранных изменений |
| `POST /api/sync/events/token` | Токен подписки владельца или `{enabled:false}`, если Ably не настроен |
| `POST /api/sync` | `{known}`: версии и изменённые записи; `{activate: true, known}` разрешает переход старой библиотеки |
| `PUT /api/sync` | `{operationId, heads, changes}`: изменения с базовыми версиями записей |
| `GET /api/sync/media?key=<key>&revision=<uuid>` | Подписанная ссылка на вложение |
| `POST /api/storage/media/upload` | Параметры загрузки `{id, sha256, md5, size, mime}` |

Устаревшая база записи возвращает `409 STALE_INDEX`, необходимость перехода: `409 MIGRATION_REQUIRED`. После перехода запись через прежний `PUT /api/storage/library` отклоняется с `409 CLIENT_UPGRADE_REQUIRED`. Старые маршруты чтения снимков сохранены для переноса данных.

При загрузке медиа используйте возвращённые метод и заголовки. B2 проверяет `Content-MD5`; SHA-256 участвует в адресации и проверке файлов клиентом. Сервер не скачивает вложения для повторного пересчёта SHA-256.

Проверки без рабочей библиотеки: `npm run test:catalog`, `npm run test:reader`, `npm run test:sync`, `npm run test:auto-sync`, `npm run test:storage` и `npm run test:e2e`. Реальная проверка B2 (`npm run test:storage -- --live --browser`) создаёт временные объекты в `idea-bank-check/<uuid>/` и требует отдельного согласования. После прерывания временные объекты могут остаться.
