# Хранение и синхронизация

Тексты и медиа хранятся вместе в закрытом Backblaze B2. Локальная копия остаётся в браузере. Настройка хранилища и CORS приведена в [руководстве по развёртыванию](deployment.md).

## Как выбирается направление

Синхронизация запускается вручную. Приложение сравнивает текущие данные с состоянием предыдущей синхронизации и версиями в облаке. Время изменения на устройстве не определяет, какая копия должна заменить другую.

| Изменения после предыдущей синхронизации | Действие |
| --- | --- |
| Только на устройстве | Отправка в облако |
| Только в облаке | Загрузка на устройство |
| Данные совпадают | Передача не требуется |
| С обеих сторон или несколько облачных веток | Выбор версии пользователем |

При первом подключении пользователь выбирает источник. При конфликте выбирается библиотека целиком; автоматического объединения текста нет. Предыдущие облачные версии сохраняются.

Перед редактированием выполните синхронизацию, после сохранения повторите её. Для нового устройства используйте тот же адрес сайта и аккаунт, затем загрузите облачную библиотеку.

## Сохранность данных

Медиа передаются до записи снимка библиотеки. При загрузке на устройство файлы проверяются по контрольным суммам; локальная библиотека заменяется после успешной подготовки вложений.

Снимки находятся в `idea-bank/v1/revisions/`, медиа в `idea-bank/v1/media/`. История и старые вложения автоматически не очищаются. Не включайте правила удаления этих объектов: они могут быть нужны предыдущим версиям.

Подписанные ссылки на вложения действуют 5 минут. Не публикуйте их: до истечения срока они дают доступ к файлу без входа. Ключи B2 остаются на сервере.

Облачная история не заменяет [ZIP-копию](../README.md#резервные-копии). После очистки браузера локальные данные потребуется восстановить из облака или архива. В уже открытой вкладке можно работать без сети; для нового открытия сайта требуется соединение.

## Ограничения

| Данные | Лимит |
| --- | --- |
| Снимок библиотеки и JSON-запрос | 3 МиБ, без медиа |
| Один медиафайл | 1 ГиБ |
| История | 10 000 снимков |
| Родители объединённой версии | 16 |

Возобновление прерванной загрузки большого файла не предусмотрено. Для скачивания библиотеки требуется свободное место под новые вложения.

## API

Запросы требуют сессии владельца. Для записи нужен `Origin`, совпадающий с `AUTH_URL`; ответы не кешируются.

| Запрос | Назначение |
| --- | --- |
| `GET /api/storage/library` | Текущий снимок и вершины истории |
| `GET /api/storage/library?revision=<uuid>` | Указанный снимок |
| `PUT /api/storage/library` | Сохранение `{baseRevisions, library, media}` |
| `POST /api/storage/media/upload` | Получение параметров загрузки `{id, sha256, md5, size, mime}` |
| `GET /api/storage/media/download?revision=<uuid>&id=<media-id>` | Ссылка на вложение снимка |

Устаревшая база или несколько веток дают `409 CONFLICT`. Для разрешения конфликта новая версия должна ссылаться на все актуальные вершины. Одновременные записи сохраняются отдельными ветками, без перезаписи друг друга.

При загрузке медиа используйте возвращённые метод и заголовки. B2 проверяет `Content-MD5`; SHA-256 используется в адресации и проверке файлов клиентом. Сервер не скачивает вложения повторно для пересчёта SHA-256.

Для проверки кода доступны `npm run test:storage` и `npm run test:sync`. Проверка настоящего B2 через `npm run test:storage -- --live --browser` создаёт и удаляет временные объекты в `idea-bank-check/<uuid>/`, не затрагивая библиотеку. После прерывания теста временные объекты могут остаться.
