# Подготовка исходников к публикации

Приложение предназначено для личных копий: другой человек скачивает или форкает репозиторий и запускает свой банк идей. Текущая версия работает локально; общие аккаунты, рабочие ключи и чужие библиотеки не должны входить в исходники.

## Что включено

- Исходный код в `app/`, `components/` и `lib/`.
- `package.json` и `package-lock.json` для воспроизводимой установки через `npm ci`.
- `README.md`, `LICENSE`, `.env.example` и конфигурация TypeScript/Playwright.
- Скрипт Windows-запуска `runIdeaBank.cmd` и папка `scripts/`.
- Браузерные тесты. Они создают синтетические данные в изолированных профилях, а не используют личную библиотеку.
- Небольшие созданные для приложения модели в `test-models/`. Это примеры файлов для тестирования, а не дополнительные идеи в стартовой библиотеке.

В `lib/ideas.ts` есть только один раздел «Примеры» и одна стартовая идея `Example`.

## Что исключено

`.gitignore` исключает зависимости, кеши, сборку, автоматически создаваемый `next-env.d.ts`, отчёты и результаты тестов, ZIP-архивы, `.env.local` и похожие локальные конфигурации, файлы ключей и папки личных данных (`backups/`, `exports/`, `private/`, `data/`, `uploads/`). `.env.example` остаётся в исходниках и сейчас содержит только пояснения.

Дублирующий `test-models.zip` не нужен в Git: исходные примеры уже находятся в `test-models/`. Архив `dist/idea-bank-source.zip` тоже не нужно коммитить.

Если секрет уже был отправлен в репозиторий, добавление его имени в `.gitignore` не удаляет файл из истории. Такая ситуация требует отдельной проверки и замены ключа.

## Проверить и собрать чистый архив

В корне приложения выполни:

```sh
npm ci
npm run source:check
npm run source:zip
```

Проверка рассматривает выбранные исходные папки и файлы, не следует по символическим ссылкам, ищет характерные форматы ключей и сохранённые JSON-библиотеки. Она выводит только имена файлов и названия найденных признаков, не значения секретов. Это вспомогательная проверка, а не гарантия распознавания любых личных данных: перед публикацией просмотри состав архива.

Архив создаётся в `dist/idea-bank-source.zip`, без зависимостей и сборки. Его содержимое можно распаковать в новую папку и проверить:

```sh
npm ci
npm run build
npm run typecheck
npm start
```

На первом запуске должна быть одна идея Example. Чистый браузерный профиль нужен, если проверяешь на том же адресе и порту, где уже была своя библиотека.

## Загрузить на GitHub

- Если пользуешься Git или GitHub Desktop, публикуй исходники с применённым `.gitignore` и проверь список файлов перед первым коммитом.
- Если загружаешь файлы вручную через сайт GitHub, используй содержимое распакованного чистого архива. Не перетаскивай туда всю рабочую папку с зависимостями, сборкой и личными файлами. Включи скрытые `.gitignore`, `.env.example`, `.npmrc` и `.nvmrc`.
- Оставь `LICENSE` в репозитории. Выбранная лицензия — MIT, автор — Idea Bank contributors.

Создание публичного репозитория и отправка кода выполняются отдельным действием владельца. Скрипт упаковки сам ничего не публикует.

## Переменные окружения

В текущем локальном режиме они не нужны. Не вставляй ключи в `.env.example`. Рабочие значения входа хранятся в `.env.local` или секретах хостинга; имена переменных есть в `.env.example`. Настройка описана в [github-login.md](github-login.md). Не используй `NEXT_PUBLIC_` для секретных ключей.
