# Дисковое хранилище локальной версии

В режиме `local` разделы, идеи, черновики и вложения сохраняются в SQLite и файлы на диске. Старые данные браузера переносятся через ZIP по [инструкции](local-migration.md); автоматического переноса или удаления нет. Облачный сайт использует [другой механизм хранения](b2-storage.md).

## Запуск

`npm run local` запускает локальный сервер, `npm run local:start` запускает предварительно собранное приложение. `runIdeaBank.cmd` устанавливает недостающие зависимости и открывает браузер. Все три варианта принудительно выбирают `local` только для процесса, сохраняя `.env.local`. `dev` и `start` используют режим из настроек и остаются доступными для проверки облачной авторизации.

Сервер привязан к `127.0.0.1`. По умолчанию используется порт 3000; другой можно передать через `--port`. Быстрый запуск повторно открывает только экземпляр из той же папки приложения и с той же папкой данных. Занятый другим приложением порт требует выбора другого порта или остановки прежнего сервера.

```sh
npm run local -- --port 3001
```

Настройки можно задать в `.env.local` или окружении процесса. `.env.example` автоматически не применяется.

| Переменная | Назначение |
| --- | --- |
| `IDEA_BANK_AUTH_MODE` | `local` по умолчанию; `github` включает вход владельца и облачную работу при настроенном B2 |
| `IDEA_BANK_DATA_DIR` | Необязательная папка дисковой библиотеки, по умолчанию `./data` |

Локальный скрипт переопределяет только режим процесса. `IDEA_BANK_DATA_DIR` продолжает учитываться. Переменные `AUTH_*`, `B2_*` и `ABLY_API_KEY` для дисковой версии не нужны. В Vercel дисковый API запрещён; публичный сайт настраивается в режиме `github` по [руководству](deployment.md).

## Папка данных

`readDiskSettings` в `lib/disk-settings.ts` по умолчанию выбирает папку `data` внутри папки приложения на всех системах. Например, для приложения в `D:\IdeaAppBank` это `D:\IdeaAppBank\data`. Папку можно переносить вместе с приложением.

Переменная `IDEA_BANK_DATA_DIR` необязательна. Она принимает относительный путь, например `./data`, или абсолютный путь к другой папке. Относительные пути разрешаются от рабочего каталога приложения (`process.cwd()`). Штатный запуск через npm и `runIdeaBank.cmd` использует корень приложения.

Папка `data` целиком исключена из Git и архива исходников, включая вложения. Для переноса библиотеки используйте ZIP-экспорт или перенос папки приложения вместе с `data`. При ручном копировании данных приложение должно быть остановлено.

Очистка данных браузера не удаляет библиотеку на диске. В браузере остаются настройки интерфейса, например язык и тема. Если выбран собственный путь `IDEA_BANK_DATA_DIR`, размещайте его вне публикуемых исходников.

## Локальный API и интерфейс

Маршруты `app/api/local` работают только в режиме `local`, вне Vercel. Они проверяют loopback-адрес, `Host`, `Origin` и `Sec-Fetch-Site` до открытия хранилища. Запрос записи требует точного адреса приложения в `Origin`. Доступ с другого сайта или из режима `github` отклоняется.

JSON-часть запроса записи ограничена 3 МиБ. Новые вложения передаются отдельно в multipart-запросе и сохраняются вместе с изменениями записей.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/local/status` | Идентификатор экземпляра для запуска, без открытия SQLite |
| `GET /api/local/library?state=1` | Версия и признак инициализации |
| `GET /api/local/catalog` | Карточки без блоков, поиск, страницы и счётчики |
| `GET /api/local/ideas/:id` | Одна идея с согласованной версией библиотеки |
| `POST /api/local/library` | Изменённые записи и их вложения одной операцией |
| `GET/HEAD /api/local/media/:id` | Файл, включая HTTP Range для видео и аудио |
| `GET /api/local/library` | Полная библиотека для явных операций с ZIP |
| `GET/POST/DELETE /api/local/drafts/:id` | Чтение, автосохранение и отмена черновика |
| `GET/POST /api/local/backup` | Снимок ZIP и защита его файлов до завершения чтения |
| `POST /api/local/example` | Добавление встроенной идеи, если её ещё нет |
| `POST /api/local/reset` | Подтверждённое удаление всех идей, разделов и черновиков |

`disk-client.ts` держит открытые данные в памяти страницы. Формы используют загруженные карточки; изменение названия и обложки не требует чтения блоков. Сохранение отправляет только изменения, а ответ обновляет счётчики. Просмотр медиа использует локальный файловый маршрут. B2, Ably и облачная очередь в локальном режиме не вызываются.

Запись защищена версией показанной пользователю библиотеки. Изменения другого окна приводят к конфликту, а не к перезаписи. Запрос содержит постоянный идентификатор операции; SQLite хранит последние 256 квитанций. Если ответ потерян, повтор с тем же содержимым получает результат уже выполненной операции. Дата и идентификатор новой идеи сохраняются при повторе формы.

Внутри папки находятся:

- `library.sqlite` и служебные файлы SQLite: разделы, карточки идей, блоки, ссылки на вложения и черновики;
- `media/`: неизменяемые вложения с именами по SHA-256;
- `temporary/`: незавершённые записи вложений.

Имена и идентификаторы пользовательских файлов не используются как пути. Одинаковое содержимое разных вложений хранится одним файлом. Базы SQLite и их служебные файлы исключены из Git и проверяются при упаковке исходников.

## Контракт модуля

`DiskLibraryStore` в `lib/disk-library.ts` открывается только явным вызовом `open`. Импорт модуля не создаёт базу. Облачный режим `github` и среда Vercel запрещены. Новая база пуста; создание Example выполняется отдельно.

| Метод | Назначение |
| --- | --- |
| `readPage` | Страница карточек без блоков, поиск, разделы и количество идей |
| `readIdea`, `readIdeaSnapshot` | Содержимое одной идеи; API получает согласованную версию библиотеки |
| `readMedia` | Проверенная ссылка на файл вложения |
| `readSnapshot` | Полная согласованная библиотека для ZIP |
| `commit` | Пакет изменений разделов и идей с проверкой версии |
| `readDraft`, `saveDraft`, `removeDraft` | Черновик с отдельной версией и ссылками на его вложения |

Карточки и блоки хранятся раздельно: чтение каталога не загружает тексты блоков. `commit` записывает переданные изменения; неизменённые идеи не перезаписываются. Удаление раздела удаляет его идеи и блоки. Перенос идеи и удаление её прежнего раздела можно выполнить одной транзакцией.

SQLite работает в режиме WAL с внешними ключами и `synchronous=FULL`. Версия библиотеки проверяется перед подготовкой файлов и повторно внутри транзакции записи. Устаревшая запись возвращает `STALE_WRITE`. Клиент должен предложить разрешить конфликт, а не повторять запись поверх новой версии.

Черновики имеют независимые версии. Их сохранение не меняет версию библиотеки. Сохранение блоков удаляет соответствующий черновик в той же транзакции; более новая версия другого окна сохраняется. Удаление идеи или раздела удаляет их черновики. После отмены остаётся служебная версия, поэтому запоздалый запрос автосохранения не может восстановить удалённый черновик. При удалении и повторном создании идеи меняется идентификатор её жизненного цикла.

Восстановление черновика получает текст и ссылки на вложения; скачивать все файлы в браузер не требуется. Повторное автосохранение не отправляет уже сохранённые вложения заново. Небольшие текстовые запросы используют `keepalive` при закрытии страницы; надёжное завершение показывается статусом «Черновик сохранён на устройстве».

ZIP содержит сохранённые идеи и медиа, без незавершённых черновиков. Импорт объединяет библиотеки, сохраняет отсутствующие в архиве идеи и требует решения для отличающихся версий. При выборе обеих версий копия получает суффикс `imported`. Одинаковые изображения в одном блоке сохраняют отдельные рамки, хотя байты на диске могут быть общими. Кнопка Example проверяет наличие идеи на сервере и добавляет встроенные файлы без полного чтения библиотеки. Подтверждение очистки не читает тела идей и медиа.

## Запись вложений и прерывание процесса

`DiskMediaStore.prepare` в `lib/disk-media.ts` принимает байты, `Blob` или поток. Файл полностью записывается во временную папку, проверяется его размер, вычисляется SHA-256 и выполняется сброс на диск. Затем файл получает постоянное имя. Только после этого транзакция SQLite сохраняет ссылки на него.

При ошибке потока временный файл удаляется. При аварийном завершении процесса SQLite откатывает незавершённую транзакцию; прежняя библиотека остаётся доступной. `collectGarbage` удаляет неиспользуемые файлы после операций удаления и при запуске. Учитываются ссылки идей, черновиков и активных операций. Неизвестные имена файлов не удаляются.

Перед публикацией нового файла сохраняется временная ссылка с PID записывающего процесса. Сборщик проверяет эти ссылки под блокировкой SQLite, поэтому не может удалить файл между записью на диск и фиксацией метаданных. Ссылки записи завершившихся процессов очищаются; временные файлы работающего процесса сохраняются. Защита ZIP действует до освобождения или истечения срока, включая перезапуск сервера.

Экспорт и проверка ZIP получают согласованный снимок и временно защищают его файлы от удаления в другом окне. Защита освобождается после операции, продлевается раз в минуту только во время чтения и истекает через 15 минут без продления. Постоянного опроса сервера для очистки нет.

Неизвестная, повреждённая база или база более новой версии не заменяется пустой. Версия схемы хранится в SQLite. Текущая схема: `3`; переходы с `1` и `2` сохраняют библиотеку, добавляют версии жизненного цикла и защиту вложений.

## Проверка

```sh
npm run test:disk-storage
npm run test:local-launch
npm run build
npm run test:disk-api
npm run test:local-migration
npm run test:requests
```

Дисковые проверки используют отдельные временные папки внутри `.cache`, реальные SQLite-файлы и синтетические вложения. Проверяются запись после перезапуска, страницы каталога, поиск, конкурирующие изменения, черновики, прерванные потоки и принудительный выход посреди транзакции. API и интерфейс проверяются на отдельном локальном сервере в широком и узком окне браузера, включая потерю ответа и новый профиль браузера. Проверка переноса охватывает прежние форматы браузера, сохранность исходных данных, отсутствующие вложения и импорт ZIP на диск. `test:requests` отдельно проверяет облачные бюджеты на синтетическом B2. Пользовательская библиотека и реальные облачные сервисы не используются.
